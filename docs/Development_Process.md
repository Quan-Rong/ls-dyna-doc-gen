## 1. 开发流程概述

### 1.1 开发原则

1. **文档先行**: 每次开发前，先更新相关文档
2. **迭代开发**: 采用敏捷开发方式，小步快跑
3. **文档同步**: 代码和文档同步更新，不滞后
4. **版本控制**: 每次迭代都要更新版本号和更新日志
5. **向后兼容**: 新功能不影响现有功能

### 1.2 开发流程总览

```
需求分析 → 架构设计 → 编码实现 → 单元测试 → 集成测试 → 文档更新 → 版本发布
    ↑                                                                        ↓
    └─────────────────────── 反馈循环 ───────────────────────────────────────┘
```

## 2. 开发阶段

### 2.1 阶段 1: 需求分析

**目标**: 明确本次迭代要实现的功能

**步骤**:
1. 阅读需求文档（`Requirements.md`）
2. 确定本次迭代的功能范围
3. 列出需要修改/新增的文件
4. 评估工作量

**输出**:
- 功能清单
- 文件清单
- 工作量评估

### 2.2 阶段 2: 架构设计

**目标**: 设计实现方案，更新架构文档

**步骤**:
1. 阅读架构文档（GUI: `../../gui_app/docs/Architecture_Design.md`，核心解析器: `architecture.md`）
2. 设计新功能的实现方案
3. 确定需要新增的模块/类/函数
4. 更新架构文档，记录设计决策

**输出**:
- 更新的架构文档
- 设计说明（如需要）

### 2.3 阶段 3: 编码实现

**目标**: 实现功能代码

**步骤**:
1. 创建/修改代码文件
2. 编写函数文档字符串（遵循模板）
3. 实现功能逻辑
4. 添加必要的注释

**要求**:
- 遵循代码规范（见 3.1 节）
- 函数必须有文档字符串
- 代码要有适当的注释

**输出**:
- 代码文件
- 函数文档（在代码中）

### 2.4 阶段 4: 单元测试

**目标**: 验证单个函数/类的正确性

**步骤**:
1. 编写单元测试用例
2. 运行测试，确保通过
3. 修复发现的 bug

**输出**:
- 测试用例
- 测试报告

### 2.5 阶段 5: 集成测试

**目标**: 验证功能整体正确性

**步骤**:
1. 运行完整的功能测试
2. 使用实际 `.key` 文件测试
3. 验证输出文档格式正确
4. 验证 GUI 界面功能正常

**输出**:
- 测试报告
- Bug 清单（如有）

### 2.6 阶段 6: 文档更新

**目标**: 更新所有相关文档

**必须更新的文档**:
1. **GUI 架构文档** (`../../gui_app/docs/Architecture_Design.md`)
   - 更新模块结构
   - 更新类/函数列表
2. **核心解析器架构文档** (`architecture.md`)
   - 更新模块结构
   - 更新类/函数列表
   - 更新数据流图（如需要）

2. **函数文档** (`Function_Documentation.md`)
   - 添加新函数的文档
   - 更新修改函数的文档

3. **更新日志** (`UPDATE_LOG.md`)
   - 记录本次迭代的变更
   - 说明新增/修改/删除的功能

4. **版本管理文档** (`Version_Management.md`)
   - 更新版本号
   - 记录版本变更内容

**输出**:
- 更新的文档文件

### 2.7 阶段 7: 版本发布

**目标**: 完成版本发布准备

**步骤**:
1. 更新版本号（在代码和文档中）
2. 生成更新日志
3. 检查所有文档完整性
4. 提交代码和文档

**输出**:
- 新版本代码
- 完整的文档
- 更新日志

## 3. 代码规范

### 3.1 Python 代码规范

**遵循标准**: PEP 8

**主要规则**:
- 使用 4 个空格缩进（不使用 Tab）
- 行长度不超过 100 字符
- 函数和类名使用驼峰命名（PascalCase）或下划线命名（snake_case）
- 常量使用大写字母和下划线
- 导入语句按标准库、第三方库、本地模块分组

**示例**:
```python
# 好的代码风格
def parse_keyword_file(file_path: str) -> dict:
    """
    解析 LS-Dyna 关键字文件。
    
    Args:
        file_path: 文件路径
        
    Returns:
        包含解析结果的字典
    """
    # 实现代码
    pass
```

### 3.2 文档字符串规范

**遵循标准**: Google Style Docstrings

**模板**:
```python
def function_name(param1: type, param2: type) -> return_type:
    """
    函数简短描述（一行）。
    
    函数详细描述（可选，多行）。
    可以说明函数的作用、算法、注意事项等。
    
    Args:
        param1: 参数1的描述
        param2: 参数2的描述
        
    Returns:
        返回值的描述
        
    Raises:
        ExceptionType: 异常情况的描述
        
    Example:
        >>> function_name("example", 123)
        {'result': 'example'}
    """
    pass
```

### 3.3 注释规范

**原则**:
- 代码应该自解释，注释用于说明"为什么"而不是"是什么"
- 复杂逻辑必须有注释
- 临时解决方案必须注释说明原因

**示例**:
```python
# 使用流式处理避免内存溢出（文件可能 > 1GB）
with open(file_path, 'r', encoding='utf-8') as f:
    for line in f:
        # 处理逻辑
        pass
```

## 4. 文档更新流程

### 4.1 文档更新时机

**必须更新的情况**:
1. 新增模块/类/函数
2. 修改函数签名或行为
3. 修改架构设计
4. 修复重要 bug
5. 性能优化

**可选更新的情况**:
1. 代码重构（不改变功能）
2. 注释改进
3. 代码风格调整

### 4.2 架构文档更新流程

**步骤**:
1. 打开相应的架构文档（GUI: `../../gui_app/docs/Architecture_Design.md`，核心解析器: `architecture.md`）
2. 找到相关章节
3. 更新模块结构图（如需要）
4. 更新类/函数列表
5. 更新数据流说明（如需要）
6. 在文档末尾的"更新记录"中记录变更

**更新内容**:
- 新增模块：添加到模块列表，说明职责
- 新增类：添加到类列表，说明功能
- 新增函数：添加到函数列表，说明用途
- 修改功能：更新相关说明

### 4.3 函数文档更新流程

**步骤**:
1. 打开 `Function_Documentation.md`
2. 找到相关模块章节
3. 添加/更新函数文档
4. 遵循函数文档模板格式

**文档格式**:
```markdown
### 模块名.类名.函数名

**位置**: `path/to/file.py:行号`

**签名**: 
```python
def function_name(param1: type, param2: type) -> return_type:
```

**描述**: 
函数功能描述

**参数**:
- `param1` (type): 参数1描述
- `param2` (type): 参数2描述

**返回**:
- `return_type`: 返回值描述

**示例**:
```python
result = function_name("example", 123)
```
```

### 4.4 更新日志更新流程

**步骤**:
1. 打开 `UPDATE_LOG.md`
2. 在文件开头添加新的更新条目
3. 按照模板格式填写
4. 记录所有变更（新增/修改/删除/修复）

**更新日志模板**:
```markdown
## [版本号] - YYYY-MM-DD

### Added
- 新增功能1
- 新增功能2

### Changed
- 修改功能1（说明原因）
- 修改功能2（说明原因）

### Fixed
- 修复 Bug1（问题描述）
- 修复 Bug2（问题描述）

### Removed
- 删除功能1（说明原因）
```

## 5. 版本管理流程

### 5.1 版本号规则

**遵循标准**: 语义化版本（Semantic Versioning）

**格式**: `主版本号.次版本号.修订号` (如 `2.1.3`)

**规则**:
- **主版本号**: 不兼容的 API 修改
- **次版本号**: 向后兼容的功能新增
- **修订号**: 向后兼容的问题修复

**示例**:
- `2.0.0` → `2.1.0`: 新增功能（GUI 界面）
- `2.1.0` → `2.1.1`: 修复 bug
- `2.1.1` → `3.0.0`: 重大架构变更（不兼容）

### 5.2 版本更新流程

**步骤**:
1. 确定版本号变更类型（主/次/修订）
2. 更新代码中的版本号（如 `__version__`）
3. 更新文档中的版本号
4. 在 `Version_Management.md` 中记录版本变更
5. 在 `UPDATE_LOG.md` 中记录详细变更

**版本号位置**:
- `main.py` 或 `__init__.py` 中的 `__version__`
- `README.md` 中的版本说明
- `CHANGELOG_CLI.md` 或 `CHANGELOG_GUI.md` 中的版本记录（根据修改的程序）
- `Version_Management.md` 中的版本历史

## 6. 测试流程

### 6.1 单元测试

**目标**: 测试单个函数/类的正确性

**要求**:
- 每个函数至少有一个测试用例
- 覆盖正常情况和边界情况
- 覆盖异常情况

**测试文件命名**: `test_<module_name>.py`

**示例**:
```python
import unittest
from ls_dyna_md.parser import LSDynaParser

class TestLSDynaParser(unittest.TestCase):
    def test_parse_node(self):
        """测试节点解析功能"""
        parser = LSDynaParser()
        result = parser.parse_node("1 0.0 0.0 0.0")
        self.assertEqual(result['id'], 1)
        self.assertEqual(result['x'], 0.0)
```

### 6.2 集成测试

**目标**: 测试功能整体正确性

**测试内容**:
1. 完整流程测试（文件输入 → 文档输出）
2. 批量处理测试
3. GUI 界面测试
4. 错误处理测试

**测试文件**: `test_integration.py`

### 6.3 测试执行

**命令**:
```bash
# 运行所有测试
python -m pytest tests/

# 运行特定测试文件
python -m pytest tests/test_parser.py

# 运行并显示覆盖率
python -m pytest tests/ --cov=ls_dyna_md
```
