## 1. 版本号规则

### 1.1 语义化版本（Semantic Versioning）

**格式**: `主版本号.次版本号.修订号` (如 `2.1.3`)

**规则**:
- **主版本号 (MAJOR)**: 不兼容的 API 修改或重大架构变更
- **次版本号 (MINOR)**: 向后兼容的功能新增
- **修订号 (PATCH)**: 向后兼容的问题修复

### 1.2 版本号示例

| 变更类型 | 示例 | 说明 |
|---------|------|------|
| 重大变更 | `2.0.0` → `3.0.0` | 架构重构，API 不兼容 |
| 新增功能 | `2.1.0` → `2.2.0` | 新增 GUI 界面功能 |
| 修复 Bug | `2.1.1` → `2.1.2` | 修复解析错误 |
| 文档更新 | `2.1.0` → `2.1.0` | 仅文档更新，不改变版本号 |

### 1.3 预发布版本

**格式**: `主版本号.次版本号.修订号-标识符` (如 `2.1.0-alpha.1`)

**标识符**:
- `alpha`: 内部测试版本
- `beta`: 公开测试版本
- `rc`: 发布候选版本

**示例**:
- `2.1.0-alpha.1`: 第一个 alpha 版本
- `2.1.0-beta.2`: 第二个 beta 版本
- `2.1.0-rc.1`: 第一个发布候选版本

## 2. 版本变更类型

### 2.1 主版本号变更 (MAJOR)

**触发条件**:
1. 重大架构变更（如从命令行工具改为 GUI 应用）
2. API 不兼容的修改
3. 数据格式不兼容的修改
4. 删除重要功能

**示例**:
- `1.x.x` → `2.0.0`: 新增 GUI 架构
- `2.0.0` → `3.0.0`: 重构解析器，API 不兼容

**版本号变化**: `X.0.0` → `(X+1).0.0`

### 2.2 次版本号变更 (MINOR)

**触发条件**:
1. 新增功能（向后兼容）
2. 新增关键字支持
3. 新增 GUI 功能
4. 性能优化（不改变接口）

**示例**:
- `2.0.0` → `2.1.0`: 新增检查清单功能
- `2.1.0` → `2.2.0`: 新增文件对比功能
- `2.2.0` → `2.3.0`: 新增 10 个关键字支持

**版本号变化**: `X.Y.0` → `X.(Y+1).0`

### 2.3 修订号变更 (PATCH)

**触发条件**:
1. Bug 修复
2. 文档修正
3. 代码重构（不改变功能）
4. 性能优化（不改变接口）

**示例**:
- `2.1.0` → `2.1.1`: 修复解析错误
- `2.1.1` → `2.1.2`: 修复 GUI 显示问题
- `2.1.2` → `2.1.3`: 修正文档错误

**版本号变化**: `X.Y.Z` → `X.Y.(Z+1)`

### 2.4 版本号不变

**情况**:
1. 仅文档更新（不涉及功能）
2. 代码注释改进
3. 代码格式调整
4. 测试用例更新

**注意**: 即使版本号不变，也要在更新日志中记录变更。

## 3. 版本更新流程

### 3.1 确定版本号

**步骤**:
1. 评估本次变更的类型（主/次/修订）
2. 参考版本变更类型（第 2 节）
3. 确定新版本号

**决策流程**:
```
有重大架构变更或 API 不兼容？
  ├─ 是 → 主版本号 +1
  └─ 否 → 有新增功能？
         ├─ 是 → 次版本号 +1
         └─ 否 → 有 Bug 修复？
                ├─ 是 → 修订号 +1
                └─ 否 → 版本号不变
```

### 3.2 更新版本号位置

**必须更新的位置**:
1. **代码中的版本号**:
   - `__version__.py`: `__version__ = "2.1.0"`
   - `main_gui.py`: 版本显示（如需要）

2. **文档中的版本号**:
   - `README.md`: 版本说明
   - `CHANGELOG_CLI.md`: CLI 程序版本记录
   - `CHANGELOG_GUI.md`: GUI 程序版本记录
   - `Version_Management.md`: 版本历史（本文档）
   - `UPDATE_LOG.md`: 更新日志

3. **配置文件**（如需要）:
   - `setup.py`: 版本号（如打包）
   - `pyproject.toml`: 版本号（如使用）

### 3.3 更新文档

**必须更新的文档**:
1. **UPDATE_LOG.md**:
   - 添加新版本条目
   - 记录所有变更（新增/修改/删除/修复）

2. **CHANGELOG_CLI.md** 和 **CHANGELOG_GUI.md**:
   - 添加新版本条目
   - 简要说明主要变更

3. **Version_Management.md** (本文档):
   - 在版本历史中添加新版本记录

4. **GUI 架构设计文档** (`gui_app/docs/Architecture_Design.md`) (如 GUI 架构变更):
   - 更新架构说明
   - 更新更新记录
   
5. **核心解析器架构文档** (`architecture.md`) (如解析器架构变更):
   - 更新架构说明
   - 更新更新记录

5. **Function_Documentation.md** (如函数变更):
   - 添加/更新函数文档

## 6. 版本号决策指南

### 6.1 常见场景

| 场景 | 版本号变化 | 示例 |
|------|-----------|------|
| 新增 GUI 主窗口 | MINOR | `2.0.0` → `2.1.0` |
| 新增检查清单功能 | MINOR | `2.1.0` → `2.2.0` |
| 新增 5 个关键字支持 | MINOR | `2.2.0` → `2.3.0` |
| 修复解析错误 | PATCH | `2.1.0` → `2.1.1` |
| 修复 GUI 显示问题 | PATCH | `2.1.1` → `2.1.2` |
| 重构架构（不兼容） | MAJOR | `2.0.0` → `3.0.0` |
| 修改 API 接口 | MAJOR | `2.0.0` → `3.0.0` |
| 仅文档更新 | 不变 | `2.1.0` → `2.1.0` |

### 6.2 特殊情况

**多个变更类型**:
- 如果同时有新增功能和 Bug 修复，按最高优先级变更类型确定版本号
- 例如：新增功能 + Bug 修复 → MINOR (`2.1.0` → `2.2.0`)

**重大 Bug 修复**:
- 如果修复了严重的安全问题或数据丢失问题，可以考虑 MINOR 而不是 PATCH
- 例如：修复数据解析错误导致的数据丢失 → MINOR

**实验性功能**:
- 实验性功能可以使用预发布版本
- 例如：`2.1.0-alpha.1` → `2.1.0-beta.1` → `2.1.0`
