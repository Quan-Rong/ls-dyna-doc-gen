## 1. 项目概述

### 1.1 项目背景

LS-Dyna 是广泛应用于汽车碰撞仿真的有限元分析软件。在实际工程中，整车碰撞模型通常由多个子模型（`.key` 文件）组成，每个子模型可能只包含部分组件（如车门、保险杠等），并不包含完整的仿真设置。

### 1.2 项目目标

开发一个 **CLI（命令行）工具**，用于：
- 批量处理 LS-Dyna `.key` 文件
- 自动生成结构化的 Markdown 文档
- 支持增量构建，节省处理时间
- 提供命令行接口，便于脚本化和自动化

### 1.3 目标用户

- **主要用户**: CAE 工程师、仿真分析人员、自动化脚本开发者
- **使用场景**: 批量文档生成、模型审查、自动化流程

## 2. 功能需求

### 2.1 核心功能（必须实现）

#### 2.1.1 文件处理功能

**FR-CLI-001: 批量文件处理**
- 自动扫描 `Input/` 目录下的所有 `.key` 文件
- 支持处理单个文件（通过命令行参数指定）
- 支持处理指定目录（通过命令行参数指定）
- 支持 `.key` 和 `.k` 文件扩展名

**FR-CLI-002: 增量构建**
- 自动检测已处理的文件（检查输出文件是否存在）
- 跳过已处理的文件，节省时间
- 提供 `--force` 选项强制重新处理所有文件

**FR-CLI-003: 文件解析**
- 解析 LS-Dyna `.key` 文件格式
- 提取关键字、参数、实体数据
- 识别未支持的关键字（用于 AI 需求生成）

#### 2.1.2 文档生成功能

**FR-CLI-004: 详细文档生成**
- 生成 `*_docs.md` - 详细参考文档
- 包含部件列表、材料列表、截面列表等
- 以表格形式展示结构化数据
- 空内容不显示（但检查清单中仍显示）

**FR-CLI-005: 概览文档生成**
- 生成 `*_overview.md` - 工程概览
- **必须包含检查清单**（9 大类分类）
- 包含物理含义总结
- 包含工程建议

**FR-CLI-006: 能力矩阵生成**
- 自动生成 `ls_dyna_md/docs/SUPPORTED_COMMANDS.md`
- 列出所有支持的关键字
- 提供关键字到数据结构的映射
- 为 AI 开发者提供参考

**FR-CLI-007: AI 需求生成**
- 当检测到未识别关键字时，生成 `*_AI_REQ.md`
- 包含未识别关键字的列表
- 包含关键字出现的行号和上下文
- 为 AI 开发者提供实现任务清单

#### 2.1.3 命令行接口

**FR-CLI-008: 命令行参数支持**
- `python cli_app/main.py` - 处理 `Input/` 目录下所有文件
- `python cli_app/main.py file.key` - 处理指定文件
- `python cli_app/main.py --force` - 强制重新生成所有文件
- `python cli_app/main.py directory/` - 处理指定目录下的所有文件

**FR-CLI-009: 输出信息**
- 显示处理进度（当前处理的文件名）
- 显示处理结果（成功/失败/跳过）
- 显示处理时间
- 显示输出文件路径

### 2.2 扩展功能（后续迭代）

**FR-CLI-010: 配置文件支持**
- 支持配置文件自定义输入/输出目录
- 支持配置文件自定义文档格式

**FR-CLI-011: 日志功能**
- 支持日志文件输出
- 支持不同日志级别（INFO/WARNING/ERROR）

**FR-CLI-012: 统计报告**
- 生成处理统计报告
- 包含处理文件数、成功数、失败数等

## 3. 非功能需求

### 3.1 性能需求

**NFR-CLI-001: 处理速度**
- 处理单个文件（100MB）应在 30 秒内完成
- 批量处理时，应支持并行处理（未来功能）

**NFR-CLI-002: 内存使用**
- 处理大文件（>1GB）时，内存使用应控制在合理范围内
- 支持流式处理，避免一次性加载整个文件到内存

### 3.2 可用性需求

**NFR-CLI-003: 错误处理**
- 友好的错误提示信息
- 处理失败时，不影响其他文件的处理
- 记录错误信息，便于排查问题

**NFR-CLI-004: 帮助信息**
- 提供命令行帮助信息（`--help`）
- 提供使用示例

### 3.3 可维护性需求

**NFR-CLI-005: 代码质量**
- 代码遵循 PEP 8 规范
- 函数和类有完整的文档字符串
- 模块化设计，便于扩展

**NFR-CLI-006: 文档完整性**
- 每次迭代更新相关文档
- 每次迭代更新更新日志

### 3.4 兼容性需求

**NFR-CLI-007: 平台支持**
- 支持 Windows 10/11
- 支持 Python 3.8+

**NFR-CLI-008: 文件格式**
- 支持标准 LS-Dyna `.key` 文件格式
- 兼容不同版本的 LS-Dyna 关键字格式

### 3.5 可扩展性需求

**NFR-CLI-009: 关键字扩展**
- 新关键字不影响现有功能
- 支持通过配置文件扩展关键字支持
- 保持向后兼容

## 4. 约束条件

### 4.1 技术约束

**CON-CLI-001: 不破坏原有程序**
- CLI 程序是现有程序，必须保持向后兼容
- 修改时不能影响现有功能

**CON-CLI-002: 保持核心功能**
- 核心解析逻辑保持不变
- 输出文档格式保持不变
- 支持的命令列表保持兼容

**CON-CLI-003: 轻量级设计**
- 不引入复杂的数据存储（如数据库）
- 保持程序轻量，易于部署
- 使用标准库，避免过多第三方依赖

### 4.2 业务约束

**CON-CLI-004: 开发时间**
- 分阶段实施，优先实现核心功能
- 每个阶段完成后进行评估

**CON-CLI-005: 资源限制**
- 使用开源技术栈
- 避免引入商业软件依赖

## 5. 用户场景

### 5.1 场景 1: 批量处理文件

**用户**: CAE 工程师  
**目标**: 批量处理多个 `.key` 文件，生成文档

**步骤**:
1. 将多个 `.key` 文件放入 `Input/` 目录
2. 运行 `python cli_app/main.py`
3. 程序自动处理所有文件
4. 在 `Output/` 目录查看生成的文档

**预期结果**: 
- 所有文件自动处理完成
- 生成详细的文档和概览文档
- 可以快速浏览每个文件的内容

### 5.2 场景 2: 处理单个文件

**用户**: 仿真分析人员  
**目标**: 处理单个 `.key` 文件

**步骤**:
1. 运行 `python cli_app/main.py Input/model.key`
2. 程序处理指定文件
3. 在 `Output/` 目录查看生成的文档

**预期结果**:
- 快速处理单个文件
- 生成详细的文档和概览文档

### 5.3 场景 3: 强制重新生成

**用户**: 项目负责人  
**目标**: 强制重新生成所有文档（即使已存在）

**步骤**:
1. 运行 `python cli_app/main.py --force`
2. 程序强制重新处理所有文件
3. 在 `Output/` 目录查看更新的文档

**预期结果**:
- 所有文件重新处理
- 文档内容更新

### 5.4 场景 4: 自动化脚本

**用户**: 自动化脚本开发者  
**目标**: 在自动化流程中集成文档生成

**步骤**:
1. 在脚本中调用 `python cli_app/main.py`
2. 检查处理结果
3. 处理生成的文档

**预期结果**:
- 可以集成到自动化流程中
- 处理结果可预测
