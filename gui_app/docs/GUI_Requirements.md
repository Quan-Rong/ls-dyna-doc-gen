## 1. 项目概述

### 1.1 项目背景

LS-Dyna 是广泛应用于汽车碰撞仿真的有限元分析软件。在实际工程中，整车碰撞模型通常由多个子模型（`.key` 文件）组成，每个子模型可能只包含部分组件（如车门、保险杠等），并不包含完整的仿真设置。

### 1.2 项目目标

开发一个 **GUI 应用程序**，用于：
- 可视化管理和分析 LS-Dyna `.key` 文件
- 自动生成结构化的 Markdown 文档
- 提供模型内容检查清单，快速了解模型包含和不包含的内容
- 支持批量处理多个文件
- 提供友好的用户界面，简化操作流程

### 1.3 目标用户

- **主要用户**: CAE 工程师、仿真分析人员
- **使用场景**: 整车碰撞模型分析、模型审查、文档生成

## 2. 功能需求

### 2.1 核心功能（必须实现）

#### 2.1.1 文件管理功能

**FR-001: 文件选择与导入**
- 用户可以通过 GUI 选择单个或多个 `.key` 文件
- 支持拖拽文件到界面
- 支持文件夹批量导入
- 显示文件列表，包括文件名、大小、修改时间

**FR-002: 文件信息显示**
- 显示选中文件的基本信息（路径、大小、修改时间）
- 显示文件处理状态（未处理/已处理/处理中/错误）

#### 2.1.2 文档生成功能

**FR-003: 自动文档生成**
- 点击处理按钮后，自动解析 `.key` 文件
- 生成以下文档：
  - `*_docs.md` - 详细参考文档（空内容不显示）
  - `*_overview.md` - 工程概览（必须包含检查清单）
  - `ls_dyna_md/docs/SUPPORTED_COMMANDS.md` - 支持的关键字列表（自动生成）
  - `*_AI_REQ.md` - 未识别关键字的实现需求（如有）

**FR-004: 批量处理**
- 支持同时处理多个文件
- 显示处理进度（进度条、百分比、当前文件）
- 支持取消正在进行的处理

**FR-005: 增量构建**
- 自动检测已处理的文件（检查输出文件是否存在）
- 跳过已处理的文件，节省时间
- 提供强制重新处理选项

#### 2.1.3 检查清单功能

**FR-006: 检查清单生成**
- 在 `*_overview.md` 中生成完整的检查清单
- 检查清单按 9 大类分类：
  1. 控制与求解器设置
  2. 边界条件与载荷
  3. 材料定义
  4. 接触定义
  5. 网格数据
  6. 截面定义
  7. 连接与约束
  8. 输出设置
  9. 其他关键字

**FR-007: 检查清单显示**
- 用 ✓ 表示包含，用空白或 ✗ 表示不包含
- 显示数量统计（如 "5个"）
- 支持按类别展开/折叠

#### 2.1.4 文档查看功能

**FR-008: 文档预览**
- 在 GUI 中预览生成的 Markdown 文档
- 支持 Markdown 渲染（显示格式化的内容）
- 支持滚动查看

**FR-009: 文档导航**
- 支持标签页切换不同文档类型（概览、详细文档等）
- 空内容标签页不显示，但检查清单中仍显示

**FR-010: 文档导出**
- 支持打开文档所在文件夹
- 支持在外部编辑器中打开文档

### 2.2 GUI 界面功能（必须实现）

#### 2.2.1 主界面布局

**FR-011: 主窗口结构**
- 左侧：文件列表区域
- 中间：内容显示区域（标签页）
- 右侧：操作按钮区域（可选）

**FR-012: 文件列表**
- 显示所有已导入的文件
- 支持多选
- 显示文件状态图标（未处理/已处理/错误）
- 支持文件排序（按名称、大小、时间）

#### 2.2.2 内容显示区域

**FR-013: 检查清单视图（默认第一个标签页）**
- 显示与 `*_overview.md` 相同的检查清单
- 按 9 大类分组显示
- 支持展开/折叠每个类别
- 显示统计信息（包含/不包含的数量）

**FR-014: 详细内容标签页**
- 根据实际内容动态显示标签页
- 空内容不显示对应标签页
- 标签页包括：
  - 控制卡片
  - 边界条件
  - 材料
  - 接触
  - 网格数据
  - 截面
  - 连接
  - 输出设置
  - 其他

**FR-015: 文档查看标签页**
- 显示完整的 `*_docs.md` 内容
- 支持 Markdown 渲染
- 支持搜索功能

#### 2.2.3 操作功能

**FR-016: 处理按钮**
- "处理选中文件" 按钮
- "处理所有文件" 按钮
- "强制重新处理" 选项（复选框）

**FR-017: 进度显示**
- 进度条显示总体进度
- 显示当前处理的文件名
- 显示已处理/总数统计

**FR-018: 状态反馈**
- 处理成功：显示成功消息
- 处理失败：显示错误消息和原因
- 处理完成：显示统计信息（成功/失败/跳过）

### 2.3 扩展功能（后续迭代）

#### 2.3.1 高级功能

**FR-019: 文件对比**
- 对比两个文件的检查清单
- 高亮显示差异

**FR-020: 统计图表**
- 显示关键字使用统计图表
- 显示模型规模统计（节点数、单元数等）

**FR-021: 关键字搜索**
- 在文档中搜索特定关键字
- 高亮显示搜索结果

**FR-022: 导出功能**
- 导出检查清单为 Excel
- 导出统计报告为 PDF

## 3. 非功能需求

### 3.1 性能需求

**NFR-001: 处理速度**
- 处理单个文件（100MB）应在 30 秒内完成
- 批量处理时，应支持后台处理，不阻塞 UI

**NFR-002: 内存使用**
- 处理大文件（>1GB）时，内存使用应控制在合理范围内
- 支持流式处理，避免一次性加载整个文件到内存

**NFR-003: 响应性**
- UI 操作响应时间 < 100ms
- 文件列表加载时间 < 2 秒（100 个文件）

### 3.2 可用性需求

**NFR-004: 用户界面**
- 界面简洁直观，符合常见 GUI 应用习惯
- 提供工具提示（Tooltip）说明功能
- 支持键盘快捷键

**NFR-005: 错误处理**
- 友好的错误提示信息
- 记录错误日志，便于排查问题
- 处理失败时，不影响其他文件的处理

**NFR-006: 帮助文档**
- 提供用户手册
- 提供常见问题解答（FAQ）

### 3.3 可维护性需求

**NFR-007: 代码质量**
- 代码遵循 PEP 8 规范
- 函数和类有完整的文档字符串
- 模块化设计，便于扩展

**NFR-008: 文档完整性**
- 每次迭代更新架构文档
- 每次迭代更新函数文档
- 每次迭代更新更新日志

**NFR-009: 版本管理**
- 使用语义化版本号（Semantic Versioning）
- 每次更新记录版本变更内容

### 3.4 兼容性需求

**NFR-010: 平台支持**
- 支持 Windows 10/11
- 支持 Python 3.8+

**NFR-011: 文件格式**
- 支持标准 LS-Dyna `.key` 文件格式
- 兼容不同版本的 LS-Dyna 关键字格式

### 3.5 可扩展性需求

**NFR-012: 关键字扩展**
- 新关键字不影响现有功能
- 支持通过配置文件扩展关键字支持
- 保持向后兼容

## 4. 约束条件

### 4.1 技术约束

**CON-001: 不破坏原有程序**
- 新架构和程序应在独立目录中开发
- 原有程序（CLI）保持不变，可继续使用

**CON-002: 保持核心功能**
- 核心解析逻辑保持不变
- 输出文档格式保持不变
- 支持的命令列表保持兼容

**CON-003: 轻量级设计**
- 不引入复杂的数据存储（如数据库）
- 保持程序轻量，易于部署

### 4.2 业务约束

**CON-004: 开发时间**
- 分阶段实施，优先实现核心功能
- 每个阶段完成后进行评估

**CON-005: 资源限制**
- 使用开源技术栈
- 避免引入商业软件依赖

## 5. 用户场景

### 5.1 场景 1: 单个文件分析

**用户**: CAE 工程师  
**目标**: 快速了解一个 `.key` 文件包含的内容

**步骤**:
1. 打开 GUI 应用程序
2. 选择或拖拽一个 `.key` 文件
3. 点击"处理"按钮
4. 查看检查清单，了解模型包含的内容
5. 查看详细文档，了解具体参数

**预期结果**: 
- 快速看到检查清单，了解模型包含哪些类型的设置
- 可以查看详细的参数信息

### 5.2 场景 2: 批量文件处理

**用户**: 项目负责人  
**目标**: 批量处理多个子模型文件，生成文档

**步骤**:
1. 打开 GUI 应用程序
2. 导入包含多个 `.key` 文件的文件夹
3. 选择"处理所有文件"
4. 查看处理进度
5. 处理完成后，查看每个文件的检查清单

**预期结果**:
- 所有文件自动处理完成
- 可以快速浏览每个文件的内容概览

### 5.3 场景 3: 模型审查

**用户**: 质量审查人员  
**目标**: 检查模型是否包含必要的设置

**步骤**:
1. 打开 GUI 应用程序
2. 导入需要审查的 `.key` 文件
3. 查看检查清单，检查是否包含：
   - 控制卡片设置
   - 边界条件
   - 材料定义
   - 接触定义
4. 对于缺失的内容，标记为问题

**预期结果**:
- 通过检查清单快速识别缺失的设置
- 提高审查效率

## 7. AI 开发者指南

### 7.1 理解需求

**阅读顺序**:
1. **本文档** - 了解 GUI 程序的功能需求
2. **GUI 入口文档** - [`GUI_ENTRY.md`](GUI_ENTRY.md) - 了解程序结构和实现细节
3. **架构设计文档** - [`Architecture_Design.md`](Architecture_Design.md) - **重点文档** - 了解 GUI 架构设计
4. **项目结构文档** - [`../../docs/Project_Structure.md`](../../docs/Project_Structure.md) - 了解项目组织方式

### 7.2 实现需求

**实现步骤**:
1. **理解需求**: 阅读本文档，明确要实现的功能
2. **理解架构**: 阅读 GUI 入口文档和架构设计文档，了解代码结构
3. **理解现有实现**: 阅读相关代码文件，了解现有实现方式
4. **实现功能**: 按照扩展指南添加代码
5. **测试功能**: 运行程序测试
6. **更新文档**: 更新相关文档

### 7.3 关键文件位置

| 需求类型 | 实现位置 | 相关文档 |
|---------|---------|---------|
| GUI 界面 | `gui_app/gui/` | [GUI_ENTRY.md](GUI_ENTRY.md), [Architecture_Design.md](Architecture_Design.md) |
| 业务逻辑 | `gui_app/controller/` | [GUI_ENTRY.md](GUI_ENTRY.md), [Architecture_Design.md](Architecture_Design.md) |
| 数据模型 | `gui_app/models/` | [GUI_ENTRY.md](GUI_ENTRY.md), [Architecture_Design.md](Architecture_Design.md) |

| 文档生成 | `ls_dyna_md/writers/` | [CLI_ENTRY.md](../../cli_app/docs/CLI_ENTRY.md) |

### 7.4 架构模式

**MVC 架构**:
- **Model**: `gui_app/models/` - 数据模型
- **View**: `gui_app/gui/` - GUI 界面
- **Controller**: `gui_app/controller/` - 业务逻辑

**数据流**:
```
用户操作 → GUI 事件 → Controller 处理 → 调用核心功能 → 更新 Model → 更新 GUI 显示
```

### 7.5 扩展指南

**添加新功能时**:
1. 确定功能属于哪个层次（GUI/Controller/Model）
2. 在相应目录下创建或修改文件
3. 遵循 MVC 架构模式
4. 添加文档字符串
5. 更新相关文档

**修改现有功能时**:
1. 确保不影响其他功能
2. 测试现有功能不受影响
3. 更新相关文档

### 7.6 技术选型

**GUI 框架**: PyQt5 或 PySide6

**理由**:
- 功能强大，界面美观
- 跨平台支持
- 丰富的组件库
- 良好的文档

### 7.7 测试需求

**测试方法**:
1. 准备测试文件（`.key` 文件）
2. 运行程序处理测试文件
3. 检查 GUI 显示是否正确
4. 验证文件处理功能
5. 验证文档生成功能
6. 验证检查清单显示功能
